# Signum translation file -> altea translation file, for translation-convert.
#
# Each line is a path base WITHOUT the `.<culture>.xml` suffix. The roots they resolve against and the
# cultures to convert are arguments of the call, so this file has exactly one kind of line.
#
# SEVERAL SOURCES MAY SHARE A TARGET, and they are merged into it: altea merges assemblies. Signum keeps
# CollectionMessage in Signum.Utilities and the rest of core in Signum, while altea has one core package;
# Signum.Excel and Signum.Word are one @altea/altea-office-template.
#
# THE REVERSE ALSO HAPPENS, ONCE: one source feeds TWO targets. Signum has no HtmlEditor assembly to keep
# translations in, so `HtmlEditorMessage` is declared in Signum CORE; altea split the editor out into
# @altea/altea-html-editor, which owns its own messages. So the core file is listed a second time, against
# that package. Over-feeding a target is the cheap direction to be wrong in: `stub-translations` rewrites
# every file from what the running process DECLARES, so core keeps everything and Altea.HtmlEditor keeps the
# 11 members and nothing else.
#
# A type is translated in the assembly that DECLARES it, so pick that one: `ActiveDirectoryMessage` lives in
# Signum.Authorization.BaseAD.ts and its strings come from Signum.Authorization, not from the stale copy in
# Signum.Authorization.WindowsAD. Where altea split one Signum type in two, translationRenames.txt
# duplicates the snippet inside the target.
#
# Signum.Calendar and Signum.Disconnected are deliberately absent: altea has neither module.
#
# A pair whose source file does not exist is skipped, so every culture can be listed once here.
